# Contributing

## Branching

- Do not commit directly to `main`.
- Use dedicated branches or worktrees for isolated work.
- Keep branch names aligned with purpose, for example `bootstrap/...`, `discovery/...`, or `adr/...`.

## Phase 0 Scope

- Only bootstrap governance, documentation, validation, planning, and empty future component boundaries are allowed.
- Product implementation is forbidden.
- Unresolved scope or architecture questions must be escalated, not guessed.

## Pull Requests

Every pull request must include:

- linked issue or approved bootstrap reference
- scope summary
- changed files summary
- validation commands and results
- assumptions and unresolved items

## Reviews

- At least one human approval is required before merge.
- Agents cannot approve or merge their own work.
- Review conversations must be resolved before merge.
