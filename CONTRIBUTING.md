# Contributing

## Branching

- Do not push directly to `main`.
- Use dedicated branches for bootstrap, discovery, and later implementation work.
- Open pull requests for all repository changes.

## Phase 0 Expectations

- Keep work limited to documentation, governance, validation, and repository harness setup.
- Do not introduce application code or infrastructure stacks.
- Resolve scope questions through ADRs, bootstrap documents, or explicit human approval.

## Pull Requests

Every pull request should explain:

- what changed
- why it changed
- how it was validated
- whether any approved decisions or open questions were affected

## Reviews

- Human approval is required before merge.
- Agents must not approve their own work.
- Review comments must be resolved or explicitly documented before merge.
