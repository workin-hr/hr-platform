# Trigger Inventory

## Trigger Name

Record the exact trigger name.

## Table

Record the table the trigger is attached to.

## Event (BEFORE/AFTER INSERT/UPDATE/DELETE)

Capture the firing point and event exactly.

## Purpose

Describe the business or technical effect of the trigger.

## Business Criticality

State whether the trigger affects customer-visible correctness, auditability,
derived data, or low-risk housekeeping.

## Replacement Notes

Capture the current best replacement hypothesis, such as application logic,
PostgreSQL trigger, scheduled reconciliation, or unresolved.

## Evidence

Link the trigger definition, dependent logic, or runtime behavior showing why
it matters.
