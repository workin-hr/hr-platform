# MySQL Events Inventory

## Event Name

Record the exact event name.

## Purpose

Describe what the event does and why it exists.

## Schedule

Capture the observed cadence or trigger. If unknown, mark it `Not yet
discovered`.

## Business Criticality

Describe whether missing or replacing the event incorrectly would affect
customer workflows, internal operations, reporting, or low-risk housekeeping.

## PostgreSQL Replacement Approach (e.g. pg_cron, external scheduler)

Capture the current best candidate approach or leave it unresolved pending
Discovery and tooling decisions.

## Evidence

Link the event definition, schedule evidence, logs, or operational notes
showing it is active and relevant.
