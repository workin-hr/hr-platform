## Findings that change the implementation plan

1. The Item 12 document's `11 / 27` employee count compares the PostgreSQL
   `com.workin.backend.employees.Employee` with MariaDB. It does **not** describe
   the current Phase 1 adapter. `LegacyEmployee` already maps all 27 MariaDB
   columns. P-5 needs endpoint read/write and payload completion, not new
   employee `@Column` mappings.
2. `status`, `otp_verified`, and `profile_completed` are `companies` columns,
   not `employees` columns. These endpoints read only `companies.id/status`
   through `requireCompanyActive`. The current `LegacyCompany` mapping is
   therefore sufficient; adding profile/onboarding columns here would widen
   Wave 12.4 into Wave 12.10.
3. `departments.manager_id` is a logical employee reference but has **no foreign
   key** in the vendored schema. `employees.department_id` has a real FK with
   `ON DELETE SET NULL`. Both must remain scalar ids; no eager JPA association is
   justified.
4. Only `employees/update.php` enforces `can_employees`, and only for an HR
   employee changing another employee. None of the other 16 endpoints enforces
   `can_employees` or another `can_*` flag.
5. Employee endpoints admit several relationship states that a generic
   in-tenant Java validator would reject: inactive branch/shift rows, a
   department validated only through a junction row, and a job title validated
   only when a department is also present. This is a security/parity decision,
   not permission to silently strengthen or reproduce the behavior.
6. The PHP hard-delete helper clears `departments.manager_id` only on the
   cascade path. If the preview finds no other related records, direct delete
   can leave a dangling manager id because the schema has no manager FK.
7. The employee endpoints depend on existing shift rows and make
   module-focused writes to `salary_contracts`, `leave_balance`, and
   `employee_shift_assignments`. They do not require the full shifts or payroll
   APIs to be ported first. The corrected 12.4 → 12.5 sequence therefore holds.
8. ADR-0011 says Phase 1 preserves the legacy URL, envelope, casing, and error
   body. Existing `com.workin.legacy` modules instead use consolidated
   `/api/legacy/**` REST routes, flat success records, and `{code,message}`
   errors; `LegacyExceptionTypePage` explicitly calls this an established
   divergence.
   **Resolved by D-074**: the literal PHP wire contract stays authoritative,
   reaffirming D-021/ADR-0003 and ADR-0011. The merged `/api/legacy/**` surface
   is implementation drift, not precedent; its retroactive correction is a
   separate follow-up boundary that Wave 12.4 must not absorb.

## B. PHP behavior matrix

### B.1 Shared guard, coercion, and response rules

| Concern | Proven PHP behavior |
|---|---|
| Body parsing | `json_decode(file_get_contents('php://input'), true) ?? []`. Invalid JSON and JSON `null` become `[]`; a scalar JSON value reaches the declared `: array` return and raises a type error/500. JSON objects become associative arrays. |
| Required fields | `required()` iterates the supplied list in order. Missing or explicit `null` fails because `isset` is false; exact `''` also fails. `0`, `'0'`, `false`, and `[]` pass. Failure: 400 `field_required`, data `{field: <name>}`. |
| PHP `empty` | Treats missing, null, false, `0`, `'0'`, `''`, and `[]` as empty. It is not interchangeable with `required()` or `array_key_exists()`. |
| Query numbers | Endpoint code uses explicit `(int)`, `(float)`, or `(string)` casts after PHP query parsing. Existing `LegacyQueryParameters`/`LegacyValues` are the reusable compatibility boundary. |
| Pagination | `page=max(1,(int)page)`. `limit=(int)(limit ?? per_page ?? default)`; falsy becomes default; clamp 1..100. Offset `(page-1)*limit`. |
| Search | `trim((string)search)`; blank means no filter. SQL `LIKE` uses `%needle%` without escaping `%` or `_`. |
| Authentication | Missing/invalid token: 401 `unauthorized_no_token`. Employee token with invalid/non-positive employee id or missing row: 401 `unauthorized_invalid_token`. Token-version mismatch: 401 `session_replaced`. Disallowed role: 403 `forbidden_insufficient_role`. |
| Company | Every endpoint, including the template, casts token company id to int and calls `requireCompanyActive`; missing/non-active company: 403 `company_account_not_active`. |
| Phase 1 tenant trust | PHP trusts the token company id. Java must retain the established extra control: tenant re-derivation from the authenticated employee, then P-1a/P-1b activation. |
| JSON envelope | `{success: bool, message: localized string}`; `data` appears only when non-null; `meta` only when non-null. `public_row` removes only `password_hash` and `token_version`. |
| Row representation | `e.*` values are raw PDO/MariaDB values. Decimal/date/enum spellings are not converted into the current PostgreSQL DTO types. Dates can include `0000-00-00`. |

Employee code is optional only under `isset`; if present normalize/digits/company-unique. Department uses `!empty` then junction validation; raw body value is inserted. Password hashes only with phone+nonblank password. Hire date raw or today. `permissions` defaults `[]` and each of 17 values is `(int)`, missing→0. |
| Roles/permissions | Admin/HR; no flag. |
| SQL/transaction | One transaction inserts employee then `INSERT ... ON DUPLICATE KEY UPDATE` HR permissions. Employee insert omits job title, expected hours, mobile/any-branch flags, join status, and token version so schema defaults apply. |
| Re-read | Commit occurs before id-only employee/org/permission left-join read. Permission map attached, secret fields stripped. |
| Errors/success | Phone/code/branch/department errors as above; 400 `first_name` field required; 400 `invalid_role`. Any duplicate constraint caught in the transaction is reported 409 `phone_already_exists`, even if a race involved employee code. Other Throwable returns 500 `employee_create_failed` with exception data. Missing post-commit user is 500 `user_not_found`. Success 201 `hr_user_created`. Non-array permissions causes a typed-helper error and rollback. |

#### 17. HR permission update

| Axis | Behavior |
|---|---|
| Request/coercion | PUT; required query `id`, `(int)`. Body `permissions` defaults `[]`; every known flag `(int)`, missing→0, unknown keys ignored. Non-array permissions causes an unhandled type error/500. |
| Roles/permissions | Admin/HR; no flag, no self restriction, no anti-escalation check. |
| Tenant/scope | Target pre-read is `id+company`; 404 `user_not_found`. Role must be exact `hr` or `manager`, else 403 `forbidden`. |
| SQL/transaction | Permission upsert with no explicit transaction; then id-only employee/permissions re-read. |
| Response | 200 `permissions_updated`, public row with nested all-17 permission map. |

## I. Dirty and ambiguous data questions

### Source/schema-settled facts

- Department/job-title/branch ids may be null only as described above;
  `branch_id` is schema-not-null.
- Inactive referenced rows remain readable because response joins have no active
  predicates. Create/update allow inactive branch and shift ids.
- Employee code is digits-only for these API writes and unique per company.
- Phone is globally unique at the exact DB value and globally compared through
  normalized variants in PHP.
- National id is not unique.
- Zero, empty, null, false, and arrays take different paths; tests must not
  collapse them into bean validation.
- Birth/hire dates have no endpoint date validation. Existing repository
  evidence records zero dates; raw-string mapping is required.
- Manager “team” means same branch, not `departments.manager_id` reports.

### Questions needing data or owner disposition

1. Do current employee rows contain missing, inactive, cross-company, or
   department-branch/job-department mismatched references? J1 answers counts
   only.
2. Do Excel lookup tables have duplicate case-folded/trimmed names within a
   company, making PHP's unordered last-row-wins map observable? J2 answers

### J2 — Excel lookup ambiguity (required before claiming deterministic parity)

```sql
SELECT module,
       COUNT(*) AS duplicate_normalized_name_groups,
       COALESCE(SUM(row_count - 1), 0) AS extra_rows_in_duplicate_groups
FROM (
  SELECT 'branches' AS module, company_id, LOWER(TRIM(name)) AS normalized_name,
         COUNT(*) AS row_count
  FROM branches WHERE is_active = 1
  GROUP BY company_id, LOWER(TRIM(name)) HAVING COUNT(*) > 1
  UNION ALL
  SELECT 'departments', company_id, LOWER(TRIM(name)), COUNT(*)
  FROM departments WHERE is_active = 1
  GROUP BY company_id, LOWER(TRIM(name)) HAVING COUNT(*) > 1
  UNION ALL
  SELECT 'job_titles', company_id, LOWER(TRIM(name)), COUNT(*)
  FROM job_titles WHERE is_active = 1
  GROUP BY company_id, LOWER(TRIM(name)) HAVING COUNT(*) > 1
  UNION ALL
  SELECT 'shifts', company_id, LOWER(TRIM(name)), COUNT(*)
  FROM shifts
  GROUP BY company_id, LOWER(TRIM(name)) HAVING COUNT(*) > 1
) duplicates
GROUP BY module
ORDER BY module;
```

An empty result means all four counts are zero. If duplicates exist, a second
owner decision is needed because PHP has no deterministic `ORDER BY` before
overwriting duplicate map keys.
