## 1. The two endpoints share one builder

`overall_attendance_report_build()`
(`apis/helpers/overall_attendance_report_helper.php`, 379 lines) is the whole of
both endpoints' business logic. Its own docblock says so: *"Shared by
overall_report API and attendance export."*

```text
attendance/overall_report.php ─┐
                               ├─→ overall_attendance_report_build()
attendance/export.php ─────────┘        (via data_export_attendance_csv():321)
```

`overall_report.php` strips the internal `_period_from` / `_period_to` keys and
calls `ok()`. `export.php` passes the same rows to the workbook writer.

**Consequence for sequencing: this is one port with two response shapes, not two
ports.** Building `overall_report.php` first leaves `export.php` owing only its
workbook rendering and its `type=fingerprints|details|days` second sheet.

## 3. Behaviours the port must preserve literally

Read out of the builder, in the order it applies them.

### 3.1 The period is clamped to elapsed days

```php
$as_of = payroll_calculation_as_of_date($period_to);
$range_to = payroll_period_in_progress($period_to, $as_of) ? $as_of : $period_to;
```

While the selected period is still open, only elapsed days enter attendance,
absence and paid-rest maths — future days are **not** absence. `total_days_in_period`
is `diff($period_from, $range_to)->days + 1`, or `0` when `$range_to < $period_from`.

Every downstream helper receives `$range_to`, not `$period_to` — except
`payroll_expected_work_days_until()`, which receives **both** `$period_to` and
`$as_of`. Passing `$range_to` there would change the result.

### 3.2 Missing dates fall back to the current month

`from`/`to` empty → `month`/`year` filters, defaulting to `date('n')`/`date('Y')`,
then `from = Y-m-01` and `to = date('Y-m-t')`. An unparseable date, or
`from > to`, is `fail(LangKey::INVALID_DATE, 400)`.

### 3.3 The holiday credit is gated on attendance coverage

```php
if ($present < WEEKLY_REST_MIN_COVERED_WORKDAYS) {
    $holiday_credit = 0;
}
```

Java's equivalent constant is `LegacyWeeklyRestCredit.MIN_COVERED_WORKDAYS = 3`.
The gate is applied **after** the query, on `present_days`, not inside the helper.

### 3.4 The absence formula

```php
$paid_due       = min(max(0, $expected_work_days_due),
                      max(0, $present) + $paid_leave_days + (int) round($holiday_credit));
$workday_absent = max(0, $expected_work_days_due - $paid_due);
$absent         = $workday_absent + max(0, $void_weekly_rest);
```

Unearned weekly rest counts as unpaid absence. `$holiday_credit` is rounded at
each use rather than once — `(int) round(...)` appears separately in `$paid_due`,
in `$paid_rest_days`, in `$effective_present` and in `paid_rest_details`, while
the row's own `official_holiday_days` carries the **unrounded** value.

### 3.5 Role scoping happens in the WHERE clause

- `employee` → forced to `e.id = auth.employee_id`; the `employee_id`,
  `branch_id` and `department_id` filters are **not** applied.
- `manager` → `sql_manager_same_branch_scope()` appended.
- anyone else → the three filters apply if non-zero.

### 3.6 Ordering is numeric-then-lexical on employee code

```sql
ORDER BY CAST(NULLIF(e.employee_code, '') AS UNSIGNED) ASC,
         e.employee_code ASC, e.first_name ASC, e.last_name ASC
```

SQL-observable ordering is part of the contract (D-111).

### 3.7 The empty-period row is a distinct shape

When `total_days_in_period <= 0`, `employee_id <= 0`, or `range_to < period_from`,
the builder emits a **zeroed row with the same keys** and `continue`s — it does
not skip the employee. `paid_rest_details` still carries its three labelled
entries with `value => 0`.

### 3.8 Row keys

24 keys, four of them nested lists (`present_details`, `absent_details`,
`exception_details`, `paid_rest_details`). `_period_from` and `_period_to` are
internal: `overall_report.php` strips them, `export.php` reads them for the
filename range.

`branch_name` and `department_name` are `null` when empty-string, not `''`.

## 4. `export.php` — what it adds beyond the builder

| Concern | Detail |
|---|---|
| Config gate | `show_export_overall_sheet` / `show_export_fingerprints_sheet` (`app_config_value`, default `'true'`); a disabled sheet is `fail(FORBIDDEN, 403)` |
| Branch | `type` in `fingerprints\|details\|days` → `data_export_fingerprints_sheet()`, else `data_export_attendance_csv()` |
| Response | `api_xlsx_export_send()` — **XLSX**, despite the `_csv` name |
| Filename | `overall_attendance_{from}_{to}.xlsx`, dates taken from the first row's `_period_*` |
| Sheet name | `الشيت الإجمالي` when the locale is `ar`, else `Overall Sheet`; `right_to_left` follows the locale |

Per D-085 and §5 G3, parity is the **reader-observable workbook** plus headers —
not the archive bytes.
