# Business Rule Extraction

## Rule

State the business rule in a way that a reviewer can test or challenge.

## Current Behavior

Describe what the current system actually does, including edge cases, default
handling, or exceptions if observed.

## Where Observed

Record where the rule appears, such as controller logic, PHP templates, SQL,
cron behavior, client-side checks, or operator workflow.

## Evidence

Link the evidence proving the rule is real. Prefer more than one source when
the rule is high risk or customer-visible.

## Risk If Misinterpreted

Describe the consequence of getting the rule wrong during redesign or
migration, such as payroll impact, attendance miscount, access-control error,
or low-risk cosmetic variance.
